# 自主导航架构与接口设计（xiaozhi-pcb-arm）

> 状态：设计稿（v0.1），只描述架构与接口，不含实现。
> 目标读者：后续实现固件行为层、以及需要对接上位机/前端的开发者。

## 1. 目标与非目标

### 1.1 目标

| 编号 | 目标 | 验收标准 |
| --- | --- | --- |
| G1 | 语音下达语义任务（"向前走两米""绕过前面的箱子"） | 云端 LLM 通过 MCP 工具下发目标 → 车在 3s 内开始执行 |
| G2 | 本地实时避障，不依赖网络 | 断网状态下以 ≤0.4 m/s 直行，遇障碍能在 40cm 前停住 |
| G3 | 航点巡逻 / 定点移动 | 5m 直线终点误差 <30cm（有 IMU）或 <60cm（纯编码器） |
| G4 | 手动/自主/急停三态切换，任何时刻可被人工抢占 | 抢占延迟 <100ms |
| G5 | 失联、雷达失效、堵转、低电压均进入安全状态 | 故障注入测试全部触发 Brake |

### 1.2 非目标（本阶段明确不做）

- 端到端视觉驾驶、深度学习策略上板
- 大场景 SLAM 建图与全局路径规划（P2 及以上，需协处理器）
- 多机协同、室外 GPS 导航
- 离线语音识别（唤醒词除外）

## 2. 约束与既有资产

### 2.1 硬件约束

| 项 | 数值 | 对设计的影响 |
| --- | --- | --- |
| MCU | ESP32-S3 双核 LX7 @240MHz，512KB SRAM + 8MB PSRAM | 可跑规则型规划，不可跑视觉模型 |
| 雷达 | LD14，UART2 115200，47B/帧 × 12 点 | 整圈约 150–200ms（5–7Hz）→ **限速主因** |
| 编码器 | 11 PPR × 4 × 减速比 76 = 3344 counts/轮圈 | 里程计分辨率足够，但履带打滑会漂 |
| 电机 | 2× AT8870，无电流反馈 | 堵转只能靠"给了指令但 rpm≈0"间接判断 |
| IMU | 组件库有 BMI270 驱动，固件未接入；本轮需外接模块 | P1 用 I2C 挂载，不占新引脚 |
| 视觉 | 无摄像头 | 视觉能力留到 P2 协处理器 |
| 低矮障碍 | 单线雷达固定扫描平面 | 必须补 ToF/超声波 + 防跌落 |

### 2.4 引脚预算与扩展方案

ESP32-S3 共 45 个 GPIO（0–21、26–48），本板已用 **25 个**：

| GPIO | 用途 |
| --- | --- |
| 0 | BOOT 按键 |
| 1 / 2 | 编码器 A（A/B 相） |
| 4 / 5 / 6 | INMP441 麦克风 |
| 7 / 15 / 16 | MAX98357 功放 |
| 9 / 10 | 双圆屏 CS（左/右） |
| 11 / 12 / 13 / 14 | 双圆屏 SCK / MOSI / DC / RST |
| 17 / 18 | 电机 A（IN1/IN2） |
| 21 / 48 | 编码器 B |
| 38 / 47 | 电机 B（IN1/IN2） |
| 39 | 雷达 UART RX |
| 40 | 雷达 PWM 调速 |
| 41 / 42 | I2C（OLED，可挂更多设备） |

**不可用**：26–32（Flash）、33–37（N16R8 的 Octal PSRAM）、22–25（S3 本身不存在）。

**空闲/有条件可用**：

| GPIO | 状态 | 说明 |
| --- | --- | --- |
| 3 | 可用 | strapping（JTAG 选择），上电瞬间勿拉低 |
| 8 | 可用 | 最干净的一个，适合 ADC/中断输入 |
| 19 / 20 | 二选一 | 原生 USB-JTAG，或给 4G 模组（两者互斥） |
| 43 / 44 | 条件 | UART0 控制台；改走 USB-JTAG 后可释放 |
| 45 | 条件 | strapping（VDD_SPI），可做输出但需确认上电电平 |
| 46 | 条件 | strapping 且 **input-only**，只能接输入 |

结论：**加 BMI270、ToF、电压计这一类传感器不需要新引脚**，因为它们都能挂在现有 I2C（41/42）上。

I2C 设备规划（地址不冲突即可共存）：

| 设备 | 地址 | 说明 |
| --- | --- | --- |
| SSD1306 OLED | 0x3C | 已有 |
| BMI270 | 0x68 / 0x69 | 6 轴 IMU，轮询 100–200Hz 足够，无需中断脚 |
| TCA9548A | 0x70 | 8 通道 I2C 复用，解决多路 ToF 同地址问题 |
| VL53L1X ×3（前/左/右） | 0x29 → 经 mux 分通道 | 也可用 XSHUT 改为 0x30/0x31/0x32 |
| INA219 / BQ27220 | 0x40 / 0x55 | 电压电流（可选，看电池采样方案） |
| PCA9685（16 路舵机） | 0x40 默认，建议改 0x41 | 与 INA219 冲突，靠 A0–A5 焊盘错开 |
| TCA9554 | 0x20 | 8 路 IO 扩展：XSHUT、按键、LED、蜂鸣器 |

I2C 带宽核算：400kHz 下，IMU 每次读取 12B、ToF 每路 2B，全部设备合计 <1KB/s，远低于总线能力。真正的约束是**布线**：I2C 不要与电机 PWM（17/18/38/47）并行走线，必要时降到 100kHz 并加 2.2kΩ 上拉。

需要真正吃引脚的外设：

| 外设 | 引脚数 | 结论 |
| --- | --- | --- |
| 摄像头（DVP） | 12+（PCLK/XCLK/VSYNC/HREF/D0–D7） | **S3 不可行**，与现有外设冲突 → P2 协处理器 |
| 超声波 ×2 | 每路 2（Trig/Echo） | 优先用 I2C ToF 替代 |
| 协处理器（P4/Pi） | 2（UART TX/RX） | 复用 43/44，或 19/20（放弃 4G/USB） |
| 4G 模组 | 2（19/20） | 已预留，与 USB 二选一 |

### 2.5 引脚不够时的优先级

1. **先上 I2C 扩展**（TCA9548A / TCA9554）——零风险，不动现有接线。
2. **释放 43/44**：控制台改走 USB-JTAG，把 UART1 让给协处理器。
3. **取舍 19/20**：要 USB 调试还是要 4G，二选一。
4. **释放 45**（输出）与 46（仅输入）——注意 strapping 上电电平。
5. **精简功能**：去掉双圆屏可一次释放 6 个引脚；雷达 PWM 固定全速可释放 GPIO40。
6. **仍不够** → 说明需求已超出 S3 定位，应上协处理器（P4/Pi），S3 只保留 2 线 UART 控制。

### 2.6 舵机扩展与 12V 供电母线

本机采用 12V 输入 + 降压，电源不再是瓶颈，但仍要按"分路、限流、时序"设计：

```
12V 输入 ──┬── 主保险 10A ──┬── AT8870 ×2（行走电机，直供 12V）
           │                ├── Buck 6V/8A ── PCA9685 V+ ── 16× 舵机
           │                └── Buck 5V/3A ── ESP32-S3 板 + LD14
           └── 输入 470µF + TVS
```

| 负载 | 电压 | 峰值电流 | 功率 |
| --- | --- | --- | --- |
| 行走电机 ×2（堵转） | 12V | 2×1.5A | 36W |
| 舵机（按 8 路常用计） | 5.5–6V | 平均 0.3A，单路堵转 2.5A | 平均 ~7W |
| ESP32-S3 + Wi-Fi | 5V | 0.5A | 2.5W |
| LD14 | 5V | 0.15A | 0.75W |
| **合计** | — | **约 6A @12V** | ~55W |

设计要点：

1. **PCA9685 的 `V+` 规格上限 5.5V**。6V 舵机普遍能跑，但建议 buck 输出设 5.5V，既在规格内又够力矩。
2. **舵机启动/堵转是脉冲负载**：buck 输出并 1000µF 电解 + 0.1µF，限流点设到 ≥5A，否则一抬臂就掉压。
3. **电机与舵机分路取电**：电机堵转会把 12V 母线拉低，若和舵机共用一路，舵机会复位或抖动。
4. **上电时序**：舵机电源经负载开关（或 MOS + 扩展 IO）控制，等 MCU 启动完成再使能，避免上电瞬间机械臂乱动。
5. **PCA9685 `OE` 接 TCA9554**：急停时硬件切断输出，不依赖软件写 0。
6. **接地**：星形共地，舵机大电流回路单独走线（AWG18），不要和 I2C/传感器地共用细线。
7. **反电动势**：舵机急停会有反向尖峰，`V+` 对地加 TVS 或肖特基。

结论：在 12V 母线 + 独立 buck 的前提下，PCA9685 只带来 **I2C 写入开销（16 路 @50Hz 约 2.9ms/20ms，放在低优先级任务）**，不占 GPIO、不影响电机 PID 与雷达解析；真正需要控制的是供电分路、地址（0x41）、总线互斥和 OE 安全。

## 3. 分层架构

```
┌─────────────────────────────────────────────────────────┐
│ 任务层（云端 / 前端 / 语音）                              │
│  LLM + MCP 工具 → 目标点、动作序列；HTTP/MQTT 手动指令      │
└───────────────────────┬─────────────────────────────────┘
                        │ Goal（异步、秒级、可取消）
┌───────────────────────▼─────────────────────────────────┐
│ 行为层 AutoTask  10Hz  Core 1  prio 4                    │
│  状态机（IDLE/AVOID/GOTO/WANDER）→ (v, w)                │
│  感知快照 → VFH 避障 → 纯跟踪 → 差速逆解                  │
└───────────────────────┬─────────────────────────────────┘
                        │ SetSpeed(l, r)  -100..100
┌───────────────────────▼─────────────────────────────────┐
│ 控制层 SpeedTask 50Hz  Core 1  prio 2（已有）             │
│  速度闭环 PID / 开环；编码器测速；堵转检测                 │
└───────────────────────┬─────────────────────────────────┘
                        │ ApplyChannel()
┌───────────────────────▼─────────────────────────────────┐
│ 安全层 SafetyTask 50Hz  Core 1  prio 5（最高）            │
│  区域判定 → 限速/急停；雷达失帧、失联、低电压、跌落        │
└─────────────────────────────────────────────────────────┘
```

### 3.1 分层原则（硬约束）

1. **安全层不依赖任何上层**：不读 MQTT、不走 HTTP、不等语音；只读雷达快照与自身状态。
2. **控制层不做决策**：只负责"把给定目标转成 PWM"，不判断障碍。
3. **行为层不碰硬件**：只调 `MotorController::SetSpeed()` 与读感知快照。
4. **任务层不参与实时环路**：LLM/前端下发的指令必须能被本地安全层随时覆盖。
5. **单一仲裁点**：所有速度指令经 `MotionArbiter` 汇聚，优先级 安全 > 手动 > 自主 > 空闲。

### 3.2 为什么不让 LLM 直接控速

云端 RTT 50–300ms，LLM 推理 0.5–3s，且链路可断。LLM 只适合"下目标"，实时环必须在板内。语音"停"这条指令也应优先走本地离线命令词（P1）或语音识别后的快速路径，不能等云端往返。

## 4. 模块设计

### 4.1 感知 Perception

输入：`ld14_driver` 的 360 分格距离/强度（已有 `s_bins[360]`，3° 融合）。
输出：固定结构的快照，避免行为层直接读驱动内部状态。

```cpp
struct ScanSnapshot {
    uint32_t stamp_ms;        // 采集完成时刻
    uint16_t valid_bins;      // 有效格数（去噪后）
    uint16_t front_mm;        // 前方 ±30° 最近距离
    uint16_t left_mm;         // 左 ±60°
    uint16_t right_mm;        // 右 ±60°
    uint16_t free_bins;       // 自由格数量
    uint8_t  hist[120];       // VFH 直方图（3°/格，0..255 越大越空）
};
```

- 过期策略：`stamp_ms` 超过 400ms 视为无效 → 安全层立即限速到 0（不等上层）。
- 聚类：按 3° 轴做一维中值滤波（窗 5），去掉孤立噪点；不做 DBSCAN（收益低、易抖动）。

### 4.2 规划 Planner（algo/navigation）

| 模式 | 算法 | 复杂度 | 说明 |
| --- | --- | --- | --- |
| AVOID | VFH-lite | O(120) | 选最佳扇区 + 障碍增益，直行优先 |
| GOTO | 纯跟踪 + 局部避障 | O(120) | 目标点 → 期望航向 → (v,w)；避障输出优先级高于跟踪 |
| WANDER | 随机漫游 + 碰障转向 | O(120) | 演示/巡检用，必须有超时保护 |

VFH-lite 判定阈值建议（可调，存 NVS）：

| 参数 | 默认 | 含义 |
| --- | --- | --- |
| `stop_mm` | 300 | 前方小于此值 → 停车并原地转向 |
| `slow_mm` | 900 | 小于此值 → 线性降速 |
| `side_mm` | 200 | 侧向安全距离 |
| `max_speed` | 40 | 自主模式占空比上限（%） |
| `rot_gain` | 0.8 | 航向误差 → 角速度增益 |

### 4.3 估计 Estimator

- P0：`odom = (Δcount_A + Δcount_B)/2 / counts_per_m`，航向由左右轮差推算。
- P1：加 BMI270，用互补滤波融合 yaw（陀螺积分 + 轮差修正），`alpha=0.98`。
- 打滑检测：同一 PWM 下 `|Δrpm|` 与历史均值偏差 >40% 且持续 200ms → 标记 `slip=true`，只降权不制动。

### 4.4 安全 Safety（优先级最高）

| 检测项 | 阈值 | 动作 |
| --- | --- | --- |
| 前方障碍 | < `stop_mm` | Brake + 置 `estop_obstacle`，需显式复位 |
| 雷达失帧 | >400ms 无有效快照 | 限速 0（滑行），恢复后自动解除 |
| 指令失联 | MQTT 2s / WS 300ms（已有） | Brake（已有） |
| 堵转 | 指令 ≥30% 但 rpm <5 持续 500ms | 反向 100ms 脱困 + Brake，计数 ≥3 次进故障 |
| 低电压 | <3.4V/cell（若接入采样） | 限速 20% 并提示回充 |

区域分级：`STOP(<300mm) / SLOW(300–900mm) / CLEAR(>900mm)`，映射到允许最大速度 `{0, 40%, max_speed}`。

制动距离（经验式，实施时用实测校正）：

```
d_brake ≈ v × (t_scan + t_ctrl + t_stop) + v²/(2a)
取 t_scan=0.20s, t_ctrl=0.03s, t_stop=0.15s, a≈1.5 m/s²
v=0.4 m/s → ≈ 0.15 + 0.05 = 0.20 m  → 建议 0.35–0.4 m 安全距离
v=1.0 m/s → ≈ 0.38 + 0.33 = 0.71 m  → 室内不可接受
```

### 4.5 仲裁 MotionArbiter

```cpp
enum class Mode { IDLE, MANUAL, AUTO_AVOID, AUTO_GOTO, AUTO_WANDER, ESTOP };

// 每个控制周期（50Hz）调用一次
SetSpeedResult Arbiter::Step(const Request& req);
// Request 来源：safety（最高）/ http / mqtt / auto_task
// 规则：safety 非 CLEAR 时忽略一切上层请求；ESTOP 需显式 Reset()
```

## 5. 接口设计

### 5.1 HTTP（设备侧，与现有 `/api/motor/*` 并列）

| 方法 | 路径 | 说明 |
| --- | --- | --- |

## 6. 时序与优先级预算

| 任务 | 周期 | 核心 | 优先级 | WCET 预算 |

## 7. 状态机

```
            ┌──────── 人工指令 ────────┐
            ▼                          │
  ┌──────────────┐   收到 Goal   ┌─────┴──────┐
  │   MANUAL     │──────────────▶│  AUTO_xxx  │
  └──────┬───────┘◀──────────────└─────┬──────┘
         │  模式关闭/完成              │ 障碍/失帧
         │                            ▼
         │                      ┌──────────┐
         └─────────────────────▶│  ESTOP   │──reset_estop（需显式）──▶ IDLE
                                └──────────┘
```

规则：
- ESTOP 只能由 `reset_estop`（HTTP/MQTT/按键）退出，且退出后回到 IDLE 而非原模式。
- 模式切换先减速到 0 再切，避免目标突变。

## 10. 测试计划

1. **单元（PC，`algo/sim`）**：VFH 扇区选择、纯跟踪收敛、里程计逆解，用录制的雷达点云回放。
2. **台架**：架空双轮，验证指令→rpm 跟踪、堵转检测、ESTOP 响应 <100ms。
3. **静态障碍**：纸箱 30/60/100cm，直行触发停车，记录最小间距与重规划次数。
4. **动态障碍**：人从侧面横穿，验证减速不撞。
5. **盲区**：玻璃、低矮拖鞋、桌沿，验证现有雷达失效场景（预期失败 → 引出 ToF 需求）。
6. **故障注入**：断网、拔雷达、卡住轮子、低电压，全部应进安全态。
7. **长跑**：30 分钟巡逻，记录复位次数、里程计漂移、CPU 峰值。

## 12. 风险与备选

| 风险 | 影响 | 备选 |
| --- | --- | --- |
| 雷达 5–7Hz 限制速度 | 巡检效率低 | 换 LD19/LD14P 230400，或降速接受 |
| 履带打滑导致里程计漂 | 航点不可用 | IMU + 视觉里程计（P2） |
| 单线雷达盲区 | 撞低矮物/玻璃 | ToF ×2 + 防跌落红外 + 机械保险杠 |
| Core0 音频已占满 | 加任务导致音频卡顿 | 显示降帧、遥测降频、必要时上双芯片 |
| 无电流反馈 | 堵转判断滞后 | 编码器+占空比偏差检测；后续加 INA219 |

## 13. 未决问题（需要实测/决策）

1. 轮径与轮距实测值（决定 `counts_per_m` 与原地转向半径）。
2. 电池电压/电流采样是否接入（决定低电压策略）。
3. 自主模式下双圆屏是否降到 10fps 或只显示静态表情。
4. 是否引入离线命令词（"停/前进/左转/右转"）作为语音安全通道。
5. P2 协处理器选型：ESP32-P4（同生态、MIPI-CSI）vs Pi Zero 2W（SLAM 生态成熟）。
